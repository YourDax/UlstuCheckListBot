# UlstuCheckListBot — трекер заданий из Telegram-группы

Находит в сообщениях группы задания и дедлайны и хранит их с предметами и статусами. Интерфейс —
Telegram-бот **@magchecklistbot** (хостится на Vercel), он же присылает утреннюю сводку и напоминания.
Локальный CLI (`python -m tracker …`) остаётся для администрирования.

## Как устроено

```
Telegram ──webhook──▶ Vercel  api/webhook.py ──▶ tracker/bot.py ──▶ Postgres (Neon)
Vercel Cron ─────────▶ Vercel  api/cron.py    ──▶ сводка и напоминания ──▶ Telegram
(позже) Telethon по расписанию ──▶ новые сообщения группы ──▶ та же база
```

* Бот приватный: отвечает только владельцу (`OWNER_ID`), остальным молчит; webhook и cron защищены секретами.
* Задания попадают в бота тремя путями: файл экспорта (`messages.html`/`result.json`) в чат с ботом,
  пересланное сообщение из группы, команда `/add`.
* Vercel не держит постоянное соединение, поэтому `watch` там не работает. Автоматическое чтение группы —
  отдельный шаг (Telethon по расписанию), он требует `api_id`/`api_hash` и сессию аккаунта в облаке.
* На тарифе Hobby Vercel Cron запускается не чаще раза в сутки: сводка приходит в 09:00 (Ульяновск), а
  напоминания «за сутки / за 3 часа» точны только при более частом внешнем запуске `/api/cron?mode=reminders`
  (например GitHub Actions раз в 15 минут с заголовком `Authorization: Bearer $CRON_SECRET`).

## Деплой на Vercel

1. **Бот.** У @BotFather: токен для @magchecklistbot (`/token`; если токен светился в чате — `/revoke`).
2. **Проект.** `vercel link` (или `vercel --prod`) в папке проекта; Python 3.13 берётся из `.python-version`.
3. **База.** В проекте на Vercel: *Storage → Create → Neon (Postgres)*. Переменная `DATABASE_URL`
   подставится автоматически (`POSTGRES_URL` тоже понимается).
4. **Переменные** (*Settings → Environment Variables*, Production; значения см. `.env.example`):
   `BOT_TOKEN`, `WEBHOOK_SECRET`, `CRON_SECRET`, `TZ_NAME`. `OWNER_ID` пока пропустите.
5. **Деплой:** `vercel --prod`, затем зарегистрируйте webhook (токен и секрет — в локальном `.env`,
   их можно получить командой `vercel env pull .env`):
   `python -m tracker webhook set https://<проект>.vercel.app/api/webhook`
6. **Свой id.** Напишите боту любое сообщение — он ответит вашим Telegram id. Добавьте его как `OWNER_ID`
   в переменные Vercel и сделайте redeploy (`vercel --prod`). После этого бот отвечает только вам.
7. **Перенос данных** (если уже импортировали локально): с `DATABASE_URL` в `.env` выполните
   `python -m tracker migrate` — перенесёт `data/tracker.db` в Postgres с теми же номерами заданий.
   Либо просто пришлите боту `messages.html` (но предметы, выставленные вручную, пропадут).

`python -m tracker webhook info` показывает адрес, очередь и последнюю ошибку доставки.

## Команды бота

`/list`, `/soon [дней]`, `/all`, `/t13` (карточка с кнопками), `/done 13`, `/doing 13`, `/reopen 13`,
`/add Название | дедлайн | предмет`, `/deadline 13 05.12 18:00`, `/subject 13 Название`, `/rm 13`,
`/find слово`, `/promote 123`, `/subjects`, `/digest`; кнопки внизу: Список, Скоро, Все, Помощь.

## Локальная работа и тесты

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements-local.txt
.venv\Scripts\python -m unittest discover -s tests -t .
```

Тесты идут на SQLite; для прогона на Postgres задайте `TEST_PG_URL=postgresql://…/имя_test` (база должна
называться `*_test`, тесты стирают её таблицы). Без `DATABASE_URL` CLI работает с `data/tracker.db`.

## Быстрый старт без Telegram-аккаунта: импорт истории

В Telegram Desktop откройте группу → ⋮ → *Экспорт истории чата* → формат **HTML или JSON** (медиа
можно не скачивать) → Экспортировать. Импорт принимает папку экспорта целиком (`messages.html`,
`messages2.html`, … или `result.json`). Затем:

```powershell
.venv\Scripts\python -m tracker import "C:\путь\к\ChatExport\result.json"
.venv\Scripts\python -m tracker list
```

Повторный импорт безопасен: задания обновляются, статусы и ручные дедлайны сохраняются. Задания с давно
прошедшим дедлайном при первом импорте сразу уходят в архив (`list --all` покажет их; отключить:
`--keep-overdue`). Если выгрузили сразу все чаты, добавьте `--chat "часть названия"`. Что не опознано как
задание, ищется через `find слово` и добавляется через `promote НОМЕР`. Позже живое слежение (`watch`) подхватит с того
сообщения, на котором остановился импорт.

## Подключение к Telegram (живое слежение)

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements-local.txt
copy .env.example .env
```

1. На https://my.telegram.org → *API development tools* создайте приложение, впишите `TG_API_ID` и
   `TG_API_HASH` в `.env`.
2. Войдите (один раз, код из Telegram и пароль 2FA вводите сами):
   `.venv\Scripts\python -m tracker login`
3. Найдите свою группу: `.venv\Scripts\python -m tracker groups` и впишите название (или id) в `TG_GROUP`.
4. Заберите историю: `.venv\Scripts\python -m tracker sync`
5. Следить постоянно: `.venv\Scripts\python -m tracker watch`

`watch` при запуске догружает всё, что пришло, пока он был выключен, и дальше ловит новые сообщения и
правки. С `NOTIFY_SAVED=1` новые задания и напоминания (за сутки и за 3 часа до дедлайна) приходят вам в
«Избранное».

## Команды

| Команда | Что делает |
|---|---|
| `import PATH [--chat X]` | загрузить историю из экспорта Telegram Desktop |
| `list [--all] [--subject S]` | открытые задания по дедлайну |
| `soon [дней]` | дедлайны в ближайшие N дней (по умолчанию 7) |
| `show ID` | полный текст и ссылка на сообщение |
| `doing ID` / `done ID` / `reopen ID` | статус |
| `add "Название" -d "завтра 18:00" -s Предмет` | задание вручную |
| `deadline ID 15.11 18:00` | поменять дедлайн (`-` — убрать); правки сообщения его уже не трогают |
| `subject ID Название` | задать предмет |
| `promote MSG_ID` | сообщение, не опознанное как задание, превратить в задание |
| `rm ID` | удалить |

Запуск: `.venv\Scripts\python -m tracker <команда>`.

## Как распознаются задания

Задание — сообщение с однозначным признаком (задание, сдать, отправить, реферат, курсовая, ДЗ, зачёт,
дедлайн, «Лабораторная работа N» …) или со сроком. Расписание («завтра лабораторные в 10:00», «лекция
11.09 19:30») заданием не считается.

Срок — дата после слов «до / к / сдать / срок / дедлайн»: `до 15.11`, `до 3 декабря в 9:00`,
`до пятницы`; для «сегодня/завтра» — если дальше «нужно отправить». Дата без таких слов берётся только в
сообщении с явным признаком задания (`Реферат 20.11`). Даты в именах файлов игнорируются. Время по
умолчанию 23:59. Промахи правятся командами `deadline`, `subject`, `promote`, `rm`.

### Предметы

Если группа — форум с темами по предметам («МНП(Долинина)», «Методы оптимизации(Дударин)» …), то при живом
слежении (`sync`/`watch`) предмет берётся из названия темы; названия «Объявления», «Расписание», «Чат»
предметами не считаются. Имя предмета подменяется на то, что записано в `subjects.json` по фамилии. В HTML-
и JSON-экспорте темы не сохраняются, поэтому для импорта работают ключевые слова ниже.

Предмет берётся из `Предмет: …` в сообщении или первого `#хештега`, а если их нет, то по ключевым словам из
[subjects.json](subjects.json): `{"Название предмета": ["Фамилия", "слово из названия"]}`. Поиск без учёта
регистра и по части слова («Долинин» найдёт и «Долининой»). Побеждает предмет, у которого совпало больше
слов. Отредактировали файл — `python -m tracker subjects` проставит предмет заданиям, у которых его ещё нет
(вручную заданные не трогает) и покажет, что осталось без предмета.

## Безопасность

`data/*.session` — это доступ к вашему Telegram: не публикуйте и не коммитьте (уже в `.gitignore`, как и
`.env`). Скрипт ничего не отправляет в группу.
